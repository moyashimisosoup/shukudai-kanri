# 完了アニメーション 仕様（4a 校了版）

利用者の校了を受けた確定仕様。**4b（本体組み込み）の発注書として使う。**

**4b で本体へ入れ終わっている。** 実装は次の3か所。数値はここが正。

- `assets/style.css` … はんこ・花丸・完走！・色（`--v1`〜`--v5`）
- `assets/app.js` … 判定（`celebrate*`）、粒のエンジン（`fx*`）、花丸、`showFinale()`
- `index.html` … `#stamp`（中身は段ごとに JS が組む）

4a の見本（`preview/kettei.html`）は 4b の完了とともに削除した。
必要な値はこの文書と `assets/` へ写してある。

## 1. 4つの段階

| 段階 | いつ | 出るもの | 長さ |
|---|---|---|---|
| 毎回 | 「できた」を押すたび | `できた！` のはんこだけ | 0.9秒 |
| **A 項目完了** | 課題を1つ終えた | `ぜんぶ できた！` のはんこ（二重の輪）＋ きらきら | 1.6秒 |
| **B 分類完了** | 必須／任意がぜんぶ終わった | 2行のはんこ ＋ 花丸（手描き）＋ 光条を強めたきらきら ＋ 弧の渦 | 4.3秒 |
| **C 完全制覇** | 必須も任意も（読書の記録もふくめて）ぜんぶ終わった | 暗転 ＋ スターマイン ＋ 弧の渦2本 ＋ 「完走！」 | 7.4秒（そのあと静止して待つ） |

**暗転するのは C だけ。** A と B は紙の上のまま。

### 出る回数（コードで確認ずみ)

- **必須・任意の課題** … `isDone` は「全部の回数／段階／ページが済んだか」で、
  いちど成立すると期間の終わりまで成立したまま。**1課題につき生涯1回。**
- **毎日の項目** … `isDone: today >= target`。日付が変わると戻るので**毎日成立する。**

したがって：

- **A の対象から毎日の項目を外す。** はんこの文字は本体のまま
  （今日ぶんが済めば「ぜんぶ できた！」）、**きらきらだけ出さない。**
- **B からも毎日の分類を外す。** 「今日の毎日をぜんぶ」は毎日成立するので、
  入れると期間中に40回ほど出る。**B は必須ぜんぶ・任意ぜんぶの2回だけ。**
  （C を「すべて終わったとき」にしてあるので、この2回は実際に出る。
  §9 を見ること。）
- 取り消し（チェックを外す）では出さない。
- C は同じ達成状態では出し直さない。端末内に「出した」しるしを残す。

## 2. はんこ

段は **輪郭の形** で付ける。色（`--suika`）も傾きもフォントも変えない。

| | 形 | 文字 |
|---|---|---|
| 毎回 | 角丸 | `できた！` |
| A | 角丸＋二重の輪 | `ぜんぶ できた！` |
| B | 角丸＋二重の輪（**2行・約1.47倍**） | 1行目 `「〈分類名〉」`／2行目 `ぜんぶ おわったよ！` |

**B ではんこを差し替えないこと。** 分類の最後の1課題を終えた瞬間は
A と B が同時に成立する。別のはんこにすると、そこで A のはんこが消える。
**足すだけ**なら、いつものはんこのまま「今回は特別」が伝わる。

### 本体側に必要な修正（重要）

本体の `.stamp-mark` は `font-size:44px` / `padding:22px 40px` が固定。
**「ぜんぶ できた！」の8文字だと iPhone の幅で 380px になる（画面390px）。**
花丸を足すと 468px で確実にあふれる。**花丸と関係なく、いま既にギリギリ。**
字も余白も可変にすること。実装した値は次のとおり（`assets/style.css`）。

    font-size : clamp(24px,6.4vw,44px)
    padding   : clamp(12px,3.4vw,22px) clamp(18px,5.6vw,40px)
    二重の輪  : padding を clamp(13px,3.7vw,24px) clamp(20px,6vw,44px) へ
    2行はんこ : font-size clamp(28px,7vw,44px) / line-height 1.34 /
                padding clamp(19px,5.4vw,35px) clamp(29px,8.8vw,65px)
    ネコの肉球: clamp(42px,11vw,72px)（実寸。em にしないこと）

### 2行の組みかた

分類名は設定で変わるうえ iPhone の幅に入らない。自動改行に任せると
「ぜん／ぶ おわったよ！」のように語の途中で割れる。
**2行を先に決め、各行に `white-space:nowrap` を置く。**

### ネコの肉球

`em` で指定しないこと。B の2行はんこは字が小さいので、`em` だと
**お祝いの場面でいちばん小さくなる。** 実寸（`clamp(42px,11vw,72px)`）で指定する。
本体の現行値は 56px / font 44px ＝ 1.27em。

## 3. 花丸（B）

**2画。** 1画目＝外から中心へ向かう渦。2画目＝もこもこ。

### 形

もこもこはエピトロコイド。`x = C·cosψ + P·cos(Lψ)`、`C=.62 P=.115 L=6`。

- **山の数は L−1。** もこもこ5つなら **L=6**（L=5 だと黙って4つになる）。
- `P` を上げるとつなぎ目が巻く。巻かないとただの波、巻きすぎると花びら。
- **極座標 `r(θ)` で書いてはいけない。** 先の切れこみ（`-cos10θ`）が
  尖った花びらを作るので、**構造的に桜になる。** もこもこは丸い山。
- 縦を `.78` に潰す（手で描く花丸は横長）。
- 非対称にする。搬送半径を「5の約数でない周期」で揺らすと山ごとに
  大きさが変わる（実測 66/67/50/61/60）。
- 揺らぎの周波数は **整数にすること。** 3.1 のような端数だと一周して
  戻ったとき半径が合わず、始点と終点に段差が出て、そこが「もうひとつの端」に見える。

### 描き始め

**跳ね返りのV字頂点（半径の極小）のうち、画面でいちばん下のもの。**
形は変えず、点列を回すだけ。実測でV字頂点は5つ、y は 38.7 / 0 / −35 / −18.4 / 21.2。

頂点を探すとき、前後3点との比較は **剰余で回すこと。** 素で `pts[i+3]` と
書くと末尾で範囲外になり、例外で点列生成ごと止まる（症状は「花丸が出ない」）。

### 描画方式（ここが最重要）

**`stroke-dasharray` / `stroke-dashoffset` を使わないこと。**

dash は「長いパターンを窓で切り出す」やり方で、線は最初から全部そこにあり
隠されているだけ。マスクの計算が少しでもズレると窓が複数箇所で開き、
**線が複数の起点から生えたように見える。** 開始位置を変えても曲線を変えても
直らなかった。

**パスの `d` 属性そのものを、描いた点までで毎フレーム作り直す。**
その瞬間に画面にある線は「先頭から n 点目まで」だけなので、
起点が増えることが原理的に起こらない。
検算：途中経過（10/30/50/80/95%）が完成形の**文字列としての接頭辞**であること。

### 時間

はんこ着地（0.56秒）→ 1画目（0.7秒）→ 0.25秒あける → 2画目（1.7秒）。
もこもこは巻きがあるぶん、ゆっくり運ばないと一筆に見えない。

### 大きさと位置

**はんこの右下、ぎりぎり重ならない位置。** はんこは画面中央のまま動かさない。

横に逃がすと画面幅に負けるが、縦は余っている。**下方向に多めに逃がす**
（右下 約75度）ことで、重ならないまま大きさを保てる。

**たてのオフセットを固定 px で決め打ちしないこと。** はんこの寸法が
変わると通用しない（はんこ幅 160→331px の拡大で実際に食いこんだ）。
はんこを描いた直後に実寸を測り、傾き11度ぶんの外接寸法から計算して
CSS変数へ入れる。

墨の半径は viewBox 半幅に対して **横 0.63 / 縦 0.58**。
配置の計算はこの実測値を使うこと（bounding box からの見積もりは二桁ずれる）。

## 4. 「完走！」（C）

はんこの延長線上。**同じ角丸、同じ枠の太さ（8px）の単線、傾きなし。**
色だけ夜空に合わせて金にする（赤のままだと暗転した空で警告に見える）。
上下の罫線は置かない（枠が囲うので二重になる）。

その下に `〈期間名〉、ぜんぶ やりきったね！`。**期間名は変数。**
本体では `periodWord(true)`（かな）を通す。文字列を直に書かない。

### 出かた

**ほかのはんこと同じ押しこみ。** ただし強さは上げる（回転 −16度、時間 0.74秒）。

**開始の拡大率を固定値にしないこと。** 3.2倍にしていたとき、iPhone では
開始時の幅が画面の 246〜355% になり、動きの大半が画面の外で起きていた。
序盤は「一面が金色」で、縮んで枠になる最後の一瞬しか見えない。
**PC では画面が広く収まるので、そこでは動いて見える** ——
環境差が出たら、まずこれを疑う。

画面幅から逆算する。ねらいは **開始時の幅が画面幅の約1.35倍**
（ふつうの「できた！」が 105〜141% で、そこは動きが見えている）。
実測で 320/390/430px すべて135%、PC（1280px）で86%。

### 押しこみを見えるようにする2つの補強

- **押される直前に周りを静める。** 生きている粒の残り寿命を 0.45秒へ
  切り詰める（消すのではなく早く終わらせるので、ぷつっと切れない）。
  まわりが動いている最中に押すと、いちばん見てほしい0.7秒が埋もれる。
- **着地の瞬間に光の輪を1回。** 枠の外側へ広がる輪。大きさの変化から
  推測させるのではなく「ここに落ちた」を明示する。

### 終わりかた

**自動で消さない。** 最後のコマ（暗い夜空と「完走！」）を保って止まる。
右上に `×`（アイコンのみ）、中央下に「もういちど」（アイコン＋文字）。

`×` は学習済みの記号なのでアイコンだけでよい。「もういちど」は
回転の矢印だけでは「もう一度見られる」と読み取れない子がいるので文字を残す。
矢印は円弧を318度にして42度の間隔を空ける（端どうしが重なると潰れて見える）。

## 5. 色

**演出の色は固定値で書かない。** `tokens.css` の5色から作り、彩度だけ
`oklch(from …)` で持ち上げる。非対応環境では素のトークンへ落とす二段構え。

```css
:root{ --v1:var(--himawari); --v2:var(--asagao); --v3:var(--wakaba);
       --v4:var(--suika);    --v5:var(--ai); }
@supports (color: oklch(from white l c h)){
  :root{
    --v1:oklch(from var(--himawari) clamp(.42,l,.74) calc(c * 1.35) h);
    --v2:oklch(from var(--asagao)   clamp(.48,l,.86) calc(c * 1.35) h);
    --v3:oklch(from var(--wakaba)   clamp(.48,l,.86) calc(c * 1.35) h);
    --v4:oklch(from var(--suika)    clamp(.48,l,.86) calc(c * 1.35) h);
    --v5:oklch(from var(--ai)       clamp(.46,l,.86) calc(c * 1.9)  h);
  }
}
```

`oklch(from …)` の `l` `c` `h` は**数値**に解決される（L は 0〜1）。
`clamp(42%, l, 86%)` のように % と混ぜると式ごと無効になり、色が丸ごと落ちる。

### 花火の色（C）

**花火の色を主に、テーマの色を弱く。** 金・橙・赤・白熱に、
テーマの紫系と緑系を「火の粉」として2色足す（白熱側へ28%寄せる）。11色中2色。

全色にテーマを22%混ぜる案は失敗だった。**6テーマとも同じ
`rgb(250,188,75)` になる。** 金にテーマの黄を混ぜていて、6テーマの黄が
ほぼ同じだから。テーマらしさは紫と緑にある。

### テーマ適合監査の結論

粒を紙（`--kami`）と背景（`--sora`）に重ねたコントラストを6テーマ分測った。
粒は文字ではないので 4.5:1 は要らないが、**1.6:1 を割ると紙の上でほぼ見えない。**

**黄（`--himawari`）だけが6テーマ全部で弱い。** 補正前 1.49〜2.05:1。
どのテーマも `--himawari` が L≒.78 と明るく、紙が L≒.99 だからで、
テーマ固有の事故ではなく**構造的なもの**。テーマ側ではなく演出側で解く。

- 黄だけ明度の上限を `.74` に下げる（ほかの4色は `.86`）。
- 粒に `--ai` のうすい輪郭（CSS は `drop-shadow`、canvas は `shadowBlur`）。
  明るい色を暗くして解くと「ひかり」に見えなくなるので、浮かせて解く。

補正後は6テーマとも下限 1.78:1 以上。

### 光り方（C）

形ではなく光り方が効く。参考画像に共通していたのは4つ。

1. **加算合成**（重なると白熱する）
2. **粒の絵** — 白熱した芯 → 色のかさ → 透明。ただの丸ではない
3. **光条** — 明るい点から伸びる十字
4. **暗い背景**

4つめは原理の話。加算合成は「下にある色に光を足す」ので、
**すでに真っ白な紙にはそれ以上足せない。** 参考画像がどれも黒背景なのは
そうでないと光として見えないから。だから C だけ暗転する。

**光条は「中心が最も太い三角形」で描いてはいけない。** 4本が重なって
中央に菱形ができ、その中に芯が乗ると「◯の穴」に見えて毒々しくなる。
細い一定幅の帯にして、強さは **長さと明るさだけ** に効かせる
（幅にも掛けると、強い段ほど汚くなる）。

かさは内側3割に詰める。広げると光条がかさに埋もれ、
「光条の先より光条の間のほうが明るい」状態になる（＝スパイクが無いのと同じ）。

## 6. prefers-reduced-motion

**演出を出さないのではなく、動かない印に置きかえる。**
「できた」ことが伝わらなくなるのは、動きが苦手な人にとっても損。

- 中くらいの達成 … 緑の丸に `✓` と「できた！」。1.4秒で消える。
- 完全制覇 … 同じ形で文字だけ「ぜんぶ できた！」。
- 透過も拡大縮小もしない。
- 判定は再生のたびに `matchMedia('(prefers-reduced-motion: reduce)')` を読む。

## 7. 表示時間の考えかた

**全体を伸ばすのではなく、出る回数の逆にする。**
毎回のものを伸ばすと必ず邪魔になり、ひと夏に数回のものは短いと
読み終わる前に消える。

入りと出は分けること。1つのキーフレームに「出る・とどまる・消える」を
入れると、**とどまる長さを段ごとに変えられない。**

## 8. 4b で本体へ入れるときの注意

- 判定は `overall()` を流用せず、**専用の関数を新しく作る**
  （`celebrateTargets()` / `celebrateGroupDone()` / `celebrateAllDone()`）。
  進捗サマリーの計算には触れない。
- 演出のかけらは1つのレイヤー要素の中だけに作る。取り残しが出ると、
  テーマを切りかえたときに古い色の粒だけが画面に残る。
  **片づけは一箇所にまとめる**（種類を増やすたびに書き足す形にすると、
  必ず消し忘れる。実際 `.group-note` の消し忘れで吹き出しが残り続けた）。
- URL の `#` には触れない。`routeFromHash()` は知らない名前を子ども画面へ落とす。
- 「出した」しるしは端末内キー。`SHARED_CONFIG_KEYS` /
  `SHARED_STATE_KEYS` の allowlist には足さない。
- canvas は CSS変数も `oklch(from …)` も読めない。描く直前に 1×1 canvas か
  probe 要素で sRGB へ解く。`getComputedStyle().getPropertyValue()` は
  `oklch(0.48 0.16 150)` の形で返るので、そこから数を3つ拾って RGB として
  扱うと**全部の色が同じ嘘の値になる**（4a で実際に踏んだ）。
- 文字の中央そろえは、`text-align:center` が揃えるのが**送り幅であって
  インクではない**ことに注意。「完走！」の「！」は全角の枠を取るのに
  インクが左寄りで、73px の字で 15.9px ずれる。canvas で字面を実測して
  差分だけ寄せる。補正は `transform` ではなく **`left`** で入れること
  （`transform` だと登場アニメと同じ性質を奪い合い、動きが消える）。

### 配信番号・公開版番号

4b では配信番号を `20260823a` → `20260823b` へ上げてある
（`index.html` と `tests/sync-regression.test.js` の版数表の両方）。
`assets/` や `index.html` を触る 4b では、`index.html` と
`tests/sync-regression.test.js` の版数表を**同時に**直すこと。片方だけだと落ちる。

## 9. 4b で決めたこと（実装後の追記）

**段の優先順位は C ＞ B ＞ A ＞ 毎回。同時に成立したら強いほうだけ出す。**
1節に順位の明記が無かったので、4b でこう決めた。C は暗転するので、
B を重ねると紙と夜空が入れかわって見えるため。

**C の条件は「必須がぜんぶ」ではなく「必須も任意も（読書の記録もふくめて）
ぜんぶ」。** 1節の表は当初「必須がぜんぶ」だったが、それだと C の条件と
B の必須版の条件が同一になり、**B の花丸がどの家庭でも一度も出ない。**
利用者の判断で「すべて終わったとき」に変更した（`celebrateAllDone()`）。
読書の記録は必須か任意のどちらかに入る課題なので、2つの分類を見れば入る。

これで花丸は2回（必須ぜんぶ・任意ぜんぶ）、完走は1回になる。

**課題が1つも無い分類は「済んだ」として数える。** 任意を1つも登録して
いない家庭で、いつまでも完走できなくなるのを防ぐ。**B はこれと違い、
空の分類では出さない**（0個を「ぜんぶ終えた」とは言わない）。

**「完走を出した」しるしは `showFinale()` の中で残す。** 押した時点で残すと、
途中で画面を閉じられたときに一度も見ていないのに「見た」ことになる。

**テーマの後始末は「変わったときだけ」。** `applyTheme()` は描き直しのたびに
呼ばれるので、素で片づけを呼ぶと保存の 60ms あとの `render()` が
出したばかりの演出を毎回消す。

**はんこの表示時間と、粒の再生時間は別々に終わらせる。**
一緒にすると B のはんこが 4.3秒ではなく 3.4秒で消える。
