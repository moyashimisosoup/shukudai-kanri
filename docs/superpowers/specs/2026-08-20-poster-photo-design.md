# 全体の写真（宿題の一覧）と、親→子の受け渡し — 設計

2026-08-20 / 対象: しゅくだいノート v1.4.0（予定）

## 何を作るか

保護者が宿題の一覧（プリント・時間割・目標表など）を1枚だけ写真で持たせ、
子どもが自分の端末でいつでも開ける。写真は各端末の中に置き、共有している家庭では
**その場で相手の端末へ渡せる**。

作らないもの（第2段階以降）:

- 各課題ごとの写真（記録としての写真）
- 2枚以上の一覧、アルバム、並べかえ

## 決まっていること（依頼者の判断）

- 差し替えられるのは**保護者ページからだけ**。子ども画面は見るだけ。
- 受け取ったら**知らせてから差し替える**（黙って変えない）。
- 共有を使っていない家庭でも、**端末内に置くところまでは使える**。
- 受け渡し箱の寿命は**24時間**。
- 設定の置き場所は保護者ページの**「宿題を決める」**（一覧は宿題の内容そのものだから）。
- 子ども画面の入口は**上の帯（タイトル行）の、日付の左**。縦を使わないため。

## データの置き場所（3層）

| 層 | 何を持つか | 同期 |
|---|---|---|
| 端末内 `natsu.photos`（IndexedDB） | 画像の本体（JPEG Blob）。id は `poster` 固定の1件 | しない |
| `config.poster = { label, at }` | ボタンのラベルと、いつのものか | 既存のconfig同期に相乗り |
| `photo_handoff/{houseId}`（Firestore） | 暗号化した画像・`at`・`from`・`expiresAt` | 一時（TTL 24時間） |

**画像そのものは config にも state にも入れない。** 入れると1文書1MiBの制限に当たり、
家庭全体の同期が止まる。`config.poster.at` は「新しいものがある」と気づくためだけの印。

## 流れ

送る（保護者端末）:

1. 写真を選ぶ（`accept="image/*"` のみ。`image/heic` は書かない。書くとSafari 17以降で
   JPEGがHEICに変換される不具合がある）
2. 長辺1280pxへ縮小し、JPEG品質0.7で再圧縮。**500KBを超えたら品質を下げて再試行**し、
   それでも超えたら断る（`encryptField` がbase64を二重にかけるため、元が約580KBを
   超えると1MiBに当たる）
3. 端末内に保存 → `config.poster` を更新（同期） → 受け渡し箱へ暗号化して書く

受け取る（子端末）:

1. `config.poster.at` が、この端末が持っている写真より新しいと気づく
2. 箱を読む → `decryptField('photo', 合言葉, …)` → 端末内へ保存
3. 「あたらしい いちらんが とどいたよ」と知らせる
4. 箱を消す（**失敗しても害はない**。TTLが消す）

読めなかったときは「印はあるが写真が無い」＝「まだ とどいていないよ」と出す。
壊れて見えないようにする。保護者はいつでも「もう一度 わたす」ができる
（あとから参加した端末には、これで届く）。

## 画面

- 子ども画面: 上の帯の、日付の左に1つボタン。ラベルは `config.poster.label`（既定
  「いちらん」）。押すと全画面で表示。**写真が無いときはボタンごと出さない。**
  新しく届いたときは、既存の `.topband-date.has-unread` と同じ小さな点で知らせる。
- 保護者ページ「宿題を決める」: 「宿題の一覧の写真」欄。選ぶ／差し替える／消す、
  ラベルの入力、「わたす」。状態は「わたしました（24時間 有効）」まで。
  **相手が受け取ったかは表示しない**（確実には分からないことを断定しない）。

## firestore.rules

`photo_handoff/{houseId}` を追加する。既存の `validHouseId()`（合言葉のSHA-256が
ドキュメントID）と匿名認証をそのまま使う。フィールドは `photo` `at` `from` `expiresAt`
の4つに限定し、サイズをルール側でもガードする。

**このパスだけ delete を許可する。** 既存は全パスで delete 禁止なので、理由をルールに
コメントで残すこと（受け取った側が自分で片づけられるようにするため）。

## 後始末（実装前に必ず決める、と調べで出た穴）

1. **TTLポリシーが必須。** 既存の90日削除の仕組み（手動ツール・未デプロイのFunction）は
   このパスを一切見ない。TTLが無いと孤児が残り続ける。Firebaseコンソールで
   `photo_handoff` の `expiresAt` にTTLを設定する。**この作業はアプリからはできない。**
2. **受け取り確認は取らない。** 読んだら消す方式は、通信が切れると「読めていないのに
   消えた」を生む。TTLに任せ、削除は補助とする。
3. **子端末が複数あっても壊れない。** 早い者勝ちで消えないので、全端末が受け取れる。

## テスト（最小限）

- `config` に画像データが混入しないこと（同期を太らせない歯止め）
- 圧縮しても上限を超える写真は断ること
- 箱へ書くのが暗号文であること（平文のdataURLがpayloadに出ない）
