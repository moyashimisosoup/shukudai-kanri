# 検討待ちの課題

着手前に設計を詰めるもの。順番は決まっていない。

## 1. 漢字レベルを小6まで選べるようにする

いまの選択肢は「すべてひらがな／小1まで／小2まで／漢字のまま」。小3〜小6も選べるようにしたい。
配当表そのものは `assets/kanji.js` に小1〜小6ぶんが既にある（`docs/kanji-grades.md` 参照）ので、
選択肢と判定の上限を広げるのが中心になる。あわせて「かなにする」の変換補助も同じ学年まで
そろえる必要がある。実装可能かの見極めから。

## 2. 小4以上を選んだときは、表現を少し大人向けにする

小4以上の語彙に合わせ、確実に理解できてわずかに背伸びした水準へそろえる。
子ども画面の文言を学年で切り替える仕組みが要るため、どこまでを切り替え対象にするかの
線引きから決める（画面の骨組みは変えない）。

## 3. できたスタンプの言葉を増やす

いまは「できた！」「ぜんぶ できた！」。「完了！」「完走！」のような言葉も出したい。
「完遂」は未習の見込みが高く、学年設定との兼ね合いで採否を決める。項目2と同じ切り替えに乗る。

## 4. 更新したことを、消えるふきだしで知らせる

v1.3.18 で新しい版を静かに取り込むようにしたが、取り込んだこと自体は画面に出していない。
「アプリが最新版（v1.3.18）に更新されました」のような、ほかの通知と同じ消えるふきだしを
出す案。問いかけではなく事実を言い切る形なので、憲章5章の「事実を言い切る」に沿う。
起動直後に出すか、前面へ戻したときだけ出すかは決めていない。

## 済み（2026年8月16日 v1.3.17 で公開）

- 記録本文に続くメモを、最後の問の答えが飲み込む → いちばん後ろの答えだけ1行に限る。
  答えとメモの境目に目じるしが無く、答えにも改行を許しているため区切りは決められない。
  余分な文が付いたまま専用欄へ移ると誤った答えとして固まるので、取りかえしのつく側を選んだ

## 決めたこと（実装の判断基準として残す）

- **安全な操作に確認を挟まない。** 確認は「そこに危険がある」と読まれ、読まずに押す習慣を作る。
  更新の取り込み、宿題の編集はどちらも確認を出さず、事実を言い切る形にした
- **「元に戻す」は時系列ではなく場所で持つ。** 直前の1回ではなく欄ごとに独立させると、
  行き来のある編集でも「いま何段階戻ったか」を利用者が覚えずに済む
- **手ごたえは、言うべきことがある時だけ出す。** 平常時の画面に要素を足さない。
  質問欄の保存ボタン、宿題編集の「元に戻す」、更新の知らせはいずれもこの原則で作った
