# 検討待ちの課題

着手前に設計を詰めるもの。順番は決まっていない。

## 1. 記録本文に続くメモを、最後の問の答えが飲み込む

旧版の記録は「・質問\n　→ 答え」を並べたあとに自由メモを `\n` でつなげている
（[app.js](../../../assets/app.js) の `saveSheet`）。`legacyQuestionAnswers` は
次の `\n・` までを答えとして取るため、**最後の問だけメモ本文まで取り込む**。

答え自体にも改行を許しているため、区切りは原理的に曖昧で、単純な規則では直せない。
次のいずれかを選ぶ必要がある。

- 最後の問だけ、取り込む範囲を1行に限る（複数行の答えが切れる）
- 旧記録の書式そのものを読み直す移行処理を書く（記録本文を書きかえることになる）
- そのままにして、利用者が入力欄で消せることをよしとする（現状）

診断の再現は S2 として確認ずみ。実害は「最後の問に余分な文が付く」ことで、
入力欄で消せるため記録は失われない。

## 済み（2026年8月16日 v1.3.16 で公開）

- メモ欄と質問欄のすみわけ →「これまでの きろく」を実装
  （[設計](2026-08-16-record-history-in-sheet-design.md)）
- iPad の端スワイプでの入力消失 → シートを開くときに履歴を1つ足し、`popstate` で
  受けとめて書きかけを確認する方式で対処
- まいにちの「0回」表示と「なおす」表記 → その日の記録が 0 のときは 0 を出さず、
  数が減るときはボタンを「なおす」にする。**コメントは「なおす」でも書ける**
  （ボタンの文言は「数がどう変わるか」、コメント欄は「何があったか」で役割が別のため、
  禁止すると覚える例外規則が増え、有用な記録も失われる）
