## 2. iPad の端スワイプでページ遷移し、入力中の内容が失われる

画面の左右端からのスワイプで Safari の戻る/進むが起きる。`.sheet-open .scroll` の
`touch-action:none`（[style.css](../../../assets/style.css)）はページ内スクロールを止めるだけで、
ブラウザのジェスチャーは防げない。

入力中の内容があるときに確認を出す方向で相談中。`beforeunload` は iOS Safari で
効きが不安定なため、`history.pushState` による戻り取り消しを含めて検討が要る。

シート内の任意質問については、× と Esc で未保存の問を知らせる確認を実装ずみ
（2026年8月16日）。端スワイプはそれとは別の経路なので、まだ塞がっていない。

## 3. 「0回」の出し方と「なおす」表記

おてつだいなど `daily` の記録で、次の整理が要る。

- **初回は「0」を出さない。** まだ1件も記録がない状態の「0」は、何を意味するか
  分からず混乱のもとになる。2回目以降、訂正の意味が生まれてから出す
- **いまの記録より少ない数を選んだときは、記録ボタンを「なおす」に変える**
- **未解決：「なおす」とコメント入力の関係。** 「なおす」かつ「コメントを書く」が
  同時に成立すると、何をしている操作なのか分からなくなる。
  「なおす」ときはコメントを書けない仕様にする案があるが、それはそれで
  ややこしいかもしれない。整理の仕方から相談する

現状の実装は [app.js](../../../assets/app.js) の `openSheet` の `daily` 分岐と
`dailyCountSelection` / `saveSheet`。0 を選んだときは
「きょうは やらなかったことに した」と記録し、はんこを出さない扱いになっている。
