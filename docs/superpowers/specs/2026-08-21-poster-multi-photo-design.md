# 宿題の一覧の写真を4枚まで持てるようにする

2026年8月21日。v1.5.4（1枚）からの拡張。依頼者の裁定は **4枚**。

## なぜ4枚か（10枚を採らない理由）

- プリントは表裏で2枚になることがある。表裏2枚＋予備2枚で、実際の用途はほぼ覆える。
- **転送は1枚＝1ドキュメント**なので、枚数だけ往復と失敗の機会が増える。
- 子どもが「どれを見ればいい？」と迷う数を超えない。一覧の目的は「ひと目で確認」。
- 端末内は4枚で約1.2MB。上限（1枚500KB）はそのまま。

## いちばん大事な決めごと：**枠は動かさない**

写真は 0〜3 の**固定の枠**に入る。2まいめを消しても3まいめは3まいめのまま。

詰め直すと、合流の合図（枠ごとの時刻）が全部ずれ、**関係のない端末が
全部の写真を取り直す**。並びを詰めるより、空いた枠が見えるほうが安い。
足すときは、いちばん小さい空き枠に入る。

## 受け渡し箱のID：**0まいめは今までのIDのまま**

| 枠 | ドキュメントID |
|---|---|
| 0 | `photo_handoff/{houseId}`（**v1.5.4 までと同じ**） |
| 1〜3 | `photo_handoff/{houseId}-1` 〜 `-3` |

こうすると、版が混ざっているあいだも壊れない。

- 旧い端末（1枚しか知らない）が渡す → 今までのIDへ書く → 新しい端末は0枚めとして受け取る。
- 新しい端末が4枚渡す → 旧い端末は今までのIDだけを見て、1枚めを受け取る。**減るが壊れない。**

`firestore.rules` は ID の形を `[0-9a-f]{64}(-[1-3])?` にするだけ。
`notRetired()` に渡すグループIDは `boxId.split('-')[0]` で取り出す。
**このルールは Firebase コンソールに貼り直すこと。** 貼らないと2枚目以降が渡らない
（1枚目は今までどおり通るので、「なぜか1枚しか届かない」という形で出る）。

## 端末の中（IndexedDB）：**0まいめは今までのキーのまま**

`poster`（＝0まいめ）／`poster-1`／`poster-2`／`poster-3`。
すでに1枚持っている家庭は、**移行の処理なしでそのまま**0まいめになる。

## 共有する設定（config.poster）

```js
config.poster = {
  label: '',              // 任意。空なら帯には印だけ（v1.5.4）
  at:  0,                 // = ats[0]。**旧い端末との互換のためにだけ置く**
  ats: [t0, t1, t2, t3]   // 枠ごとの合図。0 は「その枠は空」
}
```

- `at` に `max(ats)` を入れない。旧い端末は `at` を見て**今までのID（＝0まいめ）**を
  取りに行くので、`at` が別の枠の時刻だと、0まいめを新しいものと取りちがえる。
- 画像そのものは入れない（1文書1MiBの上限。v1.4.0 からの縛り、テストで固定）。

## 端末の控え

`natsu.poster.ats.v1`（配列）。**旧い `natsu.poster.at.v1` は残す**。
0まいめの控えは両方へ書く。旧い版へ戻ったときに、持っている写真を取り直さないため。

## 画面

**保護者ページ**：枠ごとに1行（`1まいめ／この端末にあります／[えらび直す][消す]`）。
`写真を足す` は空き枠があるときだけ。`ほかの端末へ渡す` はこの端末にある全部を渡す。
`写真を受け取る` は全部の枠を見にいく。

**子ども画面**：帯のボタンは今までどおり1つ。開いた中に**縦に並べる**。
◀▶ の送りは付けない ―― 見るだけの画面に操作を足さない。1枚のときは
これまでと同じ見え方になる（見出しの「Nまいめ」も出さない）。

## 渡しかた（**v1.6.2 で変えた。ここが最新**）

初版では、写真を選んだその場でしか箱に入らなかった。箱は24時間で空になるので、
前に登録した写真や、あとから増えた端末には自動では届かず、人が「渡す」を押す必要があった。

依頼者の裁定：**利用者は「箱に入れる」という実質の動作を関知しない。**
知りたいのは「共有されるのか」「即時か」だけで、条件で切りかわらないほうがよい。

- `refreshHandoff()`（`app.js`）が、**保護者ページを開いたときに**4つの枠の状態を見て、
  この端末が持っていて箱に無いぶんを入れ直す。読み取りは `S.handoffAts()` で4回（復号しない）、
  書き込みは欠けている枠のぶんだけ。
- **受け取っても箱を消さない。** 消すと、まだ受け取っていない端末が取り逃がす。
- これで箱はいつでも埋まり、**どの端末でも開けば届く**。
- 引きかえに、共有しているあいだ写真はほぼいつも箱にある（暗号化ずみ）。
  画面には **「共有をやめるか写真を消せば24時間以内に消えます」** と書く。
  **この一文と実装はセット。片方だけ変えないこと。**

## 掃除

- 保護者ページを開いたときの `refreshHandoff()` が、共有から外れた枠と、
  この端末が持っていない古い枠を消す。
- `sweepHandoff()`（`sync.js`）は残してあるが、いまアプリからは呼んでいない。
- `tools/retention-admin.js` は `{id}` と `{id}-1..3` を同じバッチで消す。
  **TTLは課金の有効化が前提で、このプロジェクトでは作れない**（v1.4.0 で確認済み）。

## 画面（v1.6.2〜v1.6.4 で変えた）

- 保護者ページは**画像のます目**（iPhone 2列 / 600px以上 4列）。番号とゴミ箱は写真の上へ
  かさねる。下に並べると1ますが158px（375px 実測）になり、行のころより縦を食う。
- 「写真を足す」は一覧のさいごのます。ボタンを別に並べない。
- **平常の画面に「ほかの端末へ渡す」「写真を受け取る」を出さない。**
  使い方ウインドウの `<details>「うまく届かないとき」` の中に置く。
- 使い方ウインドウの**いちばん上**に、暗号化のひとことを1行で出す（`.poster-seal`）。
- **「あずかり箱」という語を画面に出さない。** 図の中央も「クラウド」。
