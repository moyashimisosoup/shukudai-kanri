# しゅくだいノート

小学2年生が自分で使える、夏休みの宿題の進捗管理アプリ。
静的ファイルのみで動作し、GitHub Pages に置けば iPad の Safari から使えます。

> **はじめて知った方は [しゅくだいノートの紹介](https://moyashimisosoup.github.io/shukudai-notebook/docs/) をどうぞ。**
> できること、実際の画面、使い始め方をまとめています。
> 詳しい操作は [つかいかた（画面写真つき）](https://moyashimisosoup.github.io/shukudai-notebook/docs/getting-started.html) にあります。
> ファイルは [`docs/index.html`](docs/index.html) と [`docs/getting-started.html`](docs/getting-started.html)。
> このREADMEは、全機能と運用・配布のための詳しい資料です。

## URL

| | URL |
|---|---|
| **こども用** | https://moyashimisosoup.github.io/shukudai-notebook/ |
| **保護者用（進捗）** | https://moyashimisosoup.github.io/shukudai-notebook/#settings |
| 保護者用（宿題） | https://moyashimisosoup.github.io/shukudai-notebook/#tasks |
| 保護者用（設定） | https://moyashimisosoup.github.io/shukudai-notebook/#config |

こども用の画面は `のこりの しゅくだい / やったこと / カレンダー` の3タブです。記録の入力は
「のこりの しゅくだい」の各カードにある「やった！」から行うため、専用の記録タブは置いていません。
こども画面に保護者ページへの見えるボタンはありません。保護者側には「子ども画面へ」があり、
「進捗」「宿題」「設定」の3ページを上部の導線で行き来できます。

親ページを開くには URL に `#settings` を付けます。

それぞれの URL を別々にホーム画面に追加しておくと、開いた瞬間に目的の画面が出ます。

## 公開版を配るとき（複数家庭用）

公開版 `shukudai-notebook` は、1つの URL を複数家庭で使えます。各家庭は別の合言葉で別文書に分かれるため、
家庭どうしのデータは混ざりません。別の Firebase プロジェクトで独自運用する場合は、このリポジトリを複製し、
`assets/sync.js` の設定と Firestore ルールをその環境用に用意してください。

新しい URL では、保存済みデータがない端末だけ次の初期設定が開きます。

1. iPad / iPhone の「ホーム画面に追加」の案内を確認する
2. 「こどもだけでつかう」または「保護者も共有する」を選ぶ
3. 共有する場合は端末の役割を選び、最初の保護者は16文字の合言葉を作る。ほかの端末は合言葉・QRコード・招待リンクのどれかで参加する

ホーム画面に追加した iOS のアプリと Safari は別の保存領域です。追加後に開いたアイコンでも、
子ども側の「あいことばを読みこむ」を一度行ってください。

### 利用人数と資源の目安

このアプリは1グループを Firestore の1文書として扱い、通常の操作では1.2秒にまとめて書き込みます。
Firebase の無料枠は1日あたり **50,000 読み取り / 20,000 書き込み**、保存容量 1 GiB です。
そのため、2〜3台で使うグループを数十〜数百グループ規模で配る用途は十分現実的です。ただし実際の上限は、
開きっぱなしの端末数と記録頻度で決まるため、Firebase Console の Firestore「Usage」で確認してください。
上限が見え始めたら、グループごとのデータを1文書に置く方式を分割する検討が必要です。

### アクセス集計（登録グループ数）

この版では、初期設定を完了したグループ数だけを匿名で数えます。子どもの名前・宿題・記録内容は集計しません。
運用者は `?stats=family-count` をURLの末尾に付けると、通常メニューに出ない集計画面を開けます。
例：`https://<ユーザー名>.github.io/<リポジトリ名>/?stats=family-count`

この隠しURLは認証ではありません。静的ファイルを読める人なら引数を見つけられるため、
正式な管理者限定の集計が必要になった場合は、Googleログインまたはサーバー側の管理画面を追加してください。

合言葉由来の SHA-256 を中身のない重複防止マーカーの文書IDに使い、同じグループは1回だけ数えます。
誰が何回開いたか、子どもの名前、宿題、記録内容は集計用文書には保存しません。

### ペースメーター

このアプリの中心となる指標です。

```
なつやすみ  ▓▓▓▓▓▓▓▓░░░░░░░░  40%   ← 夏休みが何％過ぎたか
しゅくだい  ▓▓▓▓▓▓▓▓▓░░░░░░░  43%   ← 必須＋任意の宿題が何％終わったか
                いいペース！
```

下のバーが上のバーより先にあれば順調、という一目でわかる形にしています。
「まいにち」の項目はこの割合から外します。判定では、全体の進捗に加えて必須の宿題だけの進捗も確認します。

- 全体と必須がどちらも夏休みの経過率を `8%` 以上上回る … 「よゆうだね！」系
- 全体は先行しているが必須が遅れている … 「かならず やる」を先に進める案内
- 必須が `6%` 以上遅れている … 今日の行動を促す案内
- その他 … 「いいペース！」系

各状態に8種類以上の文言があり、同じ日の再描画では文言がころころ変わらないようにしています。
開始から2日以上、かつ全体の3%（最低2単位）以上進むと、毎日の項目を除いた平均ペースから完了予測日も表示します。
それより実績が少ないうちは、不安定な日付を出しません。

### 進捗の数え方（3種類）

| 種類 | 使う場面 | 表示 |
|---|---|---|
| `count` 番号・かず | なつスキル①〜⑭、読書のきろく20冊など | 「つぎは ⑦」＋ 棒グラフ |
| `step` だんかい式 | 読書ゆうびん、エコチャレンジ、自由研究 | 「つぎは『絵をかく』」＋ 棒グラフ |
| `daily` まいにちノルマ | トドさんすう、シンクシンク | ハートの数＋連続日数 |

`count` は記録形式を「通常」と「本の記録」から選べます。

### 本の記録

読書のきろくのように1冊ずつ内容を残したい課題は、「宿題を決める」（`#tasks`）で記録形式を「本の記録」にします。
入力欄は次の通りで、作者・出版社・おすすめ度も同じ宿題の編集欄から表示/非表示を切り替えられます。

- 本の なまえ（必須）
- さくしゃ／しゅっぱんしゃ（任意・切替可）
- よんだ日（既定は今日。あとから訂正可）
- おすすめ度 ★1〜3（任意・切替可）
- ひとこと感想

1件登録すると冊数が1つ進みます。記録した本は保護者ページの「本の記録」に一覧され、
書名・読んだ日・感想をあとから訂正できます。削除すると冊数も1つ戻り、通し番号は振り直されます。

#### 感想の漢字を2年生までに直す

感想を音声入力すると、習っていない漢字が混ざります。処理は2段階に分かれています。

**1段目「かんじを しらべる」— 通信なし・即時（実測 129ms）**

小1・小2の配当漢字240字の表と照合するだけなので、辞書は要りません。習っていない漢字を
一覧で示し、本文中の該当箇所にも色を付けます。

```
ならっていない かんじ：主　不　議　験　所　面
[主]人公が[不]思[議]な体[験]をする[所]が[面]白かった。友だちと読みたい。
```

**2段目「ぜんぶ ひらがなに して」— 辞書が必要**

読みを取るために形態素解析（kuromoji.js）を使い、習っていない漢字を含む語をまるごと
ひらがなに直した**書き写し用の文**を作ります。

```
主人公が不思議な体験をする所が面白かった。友だちと読みたい。
  ↓
しゅじんこうがふしぎなたいけんをするところがおもしろかった。友だちと読みたい。
```

「友だち」「読みたい」は友・読が小2配当なので漢字のまま残ります。

##### 直すのは語まるごと

未習の字が1文字でも入っていれば、その**語ぜんぶ**がひらがなになります。

```
面白かった  → おもしろかった   （送りがなごと直る。これは意図どおり）
水族館      → すいぞくかん     （水は小1配当だが、語ごと落ちる）
```

辞書が返すのは語全体の読み（`スイゾクカン`）だけで、どの字がどの音かは分かりません。
文字ごとに割るには音訓表に加えて連濁・音便・熟字訓（今日＝キョウ）の処理が要り、
中途半端にやると**誤った読みが黙って紙に出ます**。書き写す先が紙である以上、
まちがいを出すより語ごと落とすほうを選んでいます。

なお学年が上がるほど既習の字が増えるため、語ごと落ちる場面は減ります。

##### 辞書は Web Worker で動かす

kuromoji の辞書は**17MB をダウンロードし、95MB に展開**します。この展開と索引構築は
同期処理なので、メインスレッドで実行すると画面が数秒間フリーズします（実測：展開だけで
PC で 1.3 秒、構築を含め約 2 秒。iPad ではさらに数倍）。

そのため辞書は `assets/kanji-worker.js` の中だけで動かしています。実測でメインスレッドの
最大フレーム間隔は 29ms に収まり、読み込み中も画面は普通に触れます。

初回だけダウンロードが発生するので、**Wi-Fi 環境で最初の1回**を済ませてください。
画面にもサイズを明示しています。2回目以降はブラウザのキャッシュから読みます。
読み込めない場合でも1段目の結果は残るので、**記録そのものは必ず保存できます**。

`count` と `step` には「記録のとき出す質問」を設定できます。きゅうりの観察カードは
カード自体は1枚なので `step`（作業段階）で進捗を測り、観察の観点を質問として提示、
答えたものが記録に残ります。

### 進捗サマリー（保護者用）

「保護者用ページ → 進捗サマリー」で、今の状況をプレーンテキストに書き出せます。
コピーしてメールやメッセージに貼るか、`.txt` で保存できます。

```
■ はじめ夏休みの宿題一覧
8月6日（木） 23:42 時点

夏休み終了まで  あと 25日0時間
夏休みの経過  40%
必須の宿題    44%  (32/73)
つぎに やる  27%  (6/22)
判定  いいペース！

【かならずやる】
・なつスキル（こくご）  6/14ばん  43%  次は ⑦
・きゅうりの かんさつカード  2/5  40%  次は 「絵を かく」
✓ 学習用プリント（さんすう）  4/4まい  完了
...

【記録（直近7日）　4件】
8月6日（木）
  10:40  読書のきろく　20さつ … ⑦ できた
      ふしぎ駄菓子屋 銭天堂
```

記録の範囲は 直近7日／直近30日／全期間／含めない から選べます。

### 子どもの入力について

- 進捗の入力はすべて**タップによる選択**です。キーボード入力は不要です。
- メモ欄と観察カードの回答だけ自由記述ですが、書かなくても記録できます。
- iPad のキーボードのマイクボタンで音声入力できます。Chrome など
  Web Speech API が使えるブラウザでは 🎤 ボタンも表示されます。

## 使い方（初回）

1. 初回の「はじめの じゅんび」で、単独利用か保護者との共有かを選ぶ
2. 「アプリの設定」（`#config`）で **なつやすみ おわり** を学校から配られた日付に合わせる（初期値は 2026/08/31 23:59）
3. 「宿題を決める」（`#tasks`）で、必要なら項目名・冊数・段階・毎日のノルマを実物に合わせる

初期設定の以下の項目は、配布物が手元にないため推定で入れています。実物に合わせて調整してください。

- きゅうりのかんさつカード … 1枚。「よく見る → 高さを測る → 絵を描く → 気づいたことを書く → 日付と名前」の5段階
- なかのエコチャレンジ … 「やることを決める → 1〜7日め → 感想を書く」の9段階

## GitHub Pages への公開

```bash
cd <このリポジトリを置いたフォルダ>
git remote add origin https://github.com/<ユーザー名>/<リポジトリ名>.git
git branch -M main
git push -u origin main
```

GitHub のリポジトリで **Settings → Pages → Source: Deploy from a branch → main / (root)** を選ぶと、
数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます。

iPad の Safari でそのURLを開き、共有ボタンから **ホーム画面に追加** すると、

## データの保存場所

記録は **その端末の localStorage** に保存されます。

- Safari の履歴／サイトデータを消すと記録も消えます
- `#config` の「データ管理 → 書き出す」で JSON にバックアップできます。
  復元は同じ画面の `読みこむ` から
- 端末をまたいで共有したい場合は、次の「端末間で共有する」を設定します

## 端末間で共有する

初期状態では端末ごとに独立して保存されるため、子の iPad で入力した内容は親の端末には現れません
（消えたのではなく、そちらには最初から無い）。Firebase Firestore をつなぐと自動でそろいます。

設定していなければこれまで通り端末内だけに保存され、通信は一切発生しません。

### 1. Firebase プロジェクトを作る

1. https://console.firebase.google.com/ で「プロジェクトを追加」（Google アカウントが要ります）
2. `構築 → Firestore Database → データベースの作成`。ロケーションは `asia-northeast1`、
   モードは「本番環境」を選ぶ
3. `構築 → Authentication → 始める → Sign-in method → 匿名` を有効にする
4. `プロジェクトの設定 → マイアプリ → </> ウェブ` でアプリを登録し、表示された
   `firebaseConfig` の中身を控える

### 2. 設定を貼る

`assets/sync.js` 冒頭の `FIREBASE_CONFIG` に、控えた値を入れます。

```js
const FIREBASE_CONFIG = {
  apiKey:            'AIza...',
  authDomain:        'xxxx.firebaseapp.com',
  projectId:         'xxxx',
  storageBucket:     'xxxx.firebasestorage.app',
  messagingSenderId: '000000000000',
  appId:             '1:0000:web:0000'
};
```

この値は公開されても問題ないもので、アクセス制御は次のセキュリティルールで行います。

### 3. セキュリティルールを設定する

`Firestore Database → ルール` を、リポジトリの [`firestore.rules`](firestore.rules) の
内容にそっくり置き換えて公開します。ファイルの中にどう守っているかを書いてあります。

要点は次の3つです。

- **`list` をすべて禁止する。** アプリはコレクションの一覧を一度も使いません。
  `read` とだけ書くと `list` も許してしまい、`households` を丸ごと取得できます
- **グループ数の集計に、あいことばの手がかりを置かない。** `metrics/registrations` には
  数だけを置き、重複の判定は `metrics_households/<あいことばのSHA-256>` という
  **中身のない目印**で行います。ID を知っている＝あいことばを知っている人しか
  たどり着けないので、一覧を禁止すれば漏れません
- **書ける内容を絞る。** 欄の名前、ID の形、`count` は増える向きだけ、と限定して、
  ゴミ文書の作成や集計の改ざんを防ぎます

> **以前のルールを使っていた場合**
> `metrics/registrations` の中に `households`（あいことばの SHA-256 の一覧）が
> 残っていることがあります。**Console でこのフィールドを削除してください。**
> 一覧が読めると総当たりであいことばを割り出せるため、ルールの更新とあわせて
> 必ず消す必要があります。

### 4. 端末をつなぐ

1. 初回の保護者端末で「保護者も共有する → おうちの人の端末 → 合言葉はまだない」を選ぶ。自動で作られた16文字の合言葉でそのまま共有が始まる
2. QRコードまたは招待リンクを信頼できる家族に渡す。すでに使い始めている端末は、`#config` の「ほかの端末と共有」から同じ合言葉を入力する
3. 保護者用ページの見出しに「共有　○○と共有中」と表示されれば完了

以後、同じあいことばを入れた複数の端末で入力内容が数秒で反映されます。

> **共有コードの注意**
> 新しく作る共有コードは Firestore の文書IDへ平文では保存せず、SHA-256で変換して扱います。
> 名前・宿題・記録・共有端末の呼び名は、合言葉から PBKDF2（SHA-256、250,000回）で作る鍵と AES-GCM 256bit で端末内暗号化してから保存します。
> 鍵と合言葉は Firebase へ送らないため、Firebase プロジェクトの管理者でもその中身は読めません。暗号文は保存するたびに別のランダム IV を使います。
> 一方で、端末の役割・アプリの版・解除状態・更新時刻など、接続と競合解決に必要なメタデータは平文で保存します。
> QRコードと招待リンクには合言葉自体が含まれます。普段使うパスワードや秘密の言葉は使わず、信頼できる家族だけに渡してください。すべての端末で合言葉を失うと、クラウド上の暗号文は復元できません。

> **暗号化対応前の共有データ**
> 旧方式の文書は現行版から直接開けません。旧版の端末で JSON を書き出し、最新版で合言葉を作り直したあとに読み込んで移行してください。

#### ホーム画面に追加したアイコンは別扱い

iOS では **「ホーム画面に追加」したアイコンは Safari とは別の localStorage** を持ちます。
同じ URL でも中身は共有されないため、Safari であいことばを入れても
アイコンの方には伝わりません。**アイコンで開いた画面でも、もう一度あいことばを入力**
してください（アイコンを作り直す必要はありません）。

アイコンにはアドレス欄がなく、こども画面から保護者ページへの導線もないため、
**画面上部の色帯（タイトルの行）から保護者ページへ移動**できるようにしてあります。
入口は2つあり、どちらでも開きます。画面には何も表示されません。

- **2秒ほど長押しする**（指が多少ゆれても大丈夫。大きく動かすとスクロール扱いで取り消し）
- **とんとんと5回続けてタップする**（間隔が0.8秒以上あくと数え直し）

iOS の長押しは文字選択や虫めがねに取られて切れることがあるため、
確実な連続タップの方も用意しています。ゆっくりしたタップでは開かないので、
子どもが誤って開くことはほとんどありません。

### 合わせ方の方針

**子どもの入力が消えないことを最優先**にしています。

| データ | 合わせ方 |
|---|---|
| `logs`・`books` 記録 | id で突き合わせて**両端末ぶんを足す**。同じ id の編集は新しい方 |
| `progress.done` 番号・冊数 | 値ごとの更新時刻で、後から行った進捗や訂正を採る |
| `progress.days` 毎日ノルマ | 日付ごとに全部あわせ、同じ日の訂正はその日の更新時刻で決める |
| `progress.steps`・`wrap` 段階 | チェックごとの更新時刻で、後から行ったオン／オフを採る |
| `trash`・`gone` 削除の印 | 記録の id と削除時刻を合流し、他端末に残る古い記録の復活を防ぐ |
| `resetAt` 全削除の世代 | より新しい全削除より前の進捗と記録を破棄し、削除後の新しい記録だけを合流する |
| `config` 設定 | **後に保存した方で丸ごと置き換え**（設定は保護者が行う前提） |
| `fun` ミニコンテンツの当日回数・一巡履歴 | 共有しない（端末ごとに1日3回、宿題を記録した日は4回、184件を一巡するまで重複なし） |

**state 全体が新しいかどうかだけで上書きするのではありません。** 記録は id ごと、進捗は数値・日付・チェックごとに合流するため、
オフラインの別端末で追加した内容を残しつつ、「⑦を⑥に戻す」「本の記録を消す」などの訂正も同期できます。
値ごとの更新時刻を持たない旧版データどうしを合流する場合だけは、互換性のため従来どおり大きい数値・多い回数・チェック済みを安全側として採ります。

なお `fun`（ミニコンテンツの1日3回と一巡履歴）を共有すると、保護者がページを開いただけで
子の回数が減ってしまうため、これだけは送信しません。

### 制約

- 共有中のすべての端末を同じ版にそろえてください。更新時刻や削除の印を知らない古い版が残ると、訂正前の値を送り返すことがあります
- 保存の主体は今も localStorage です。起動は通信を待たず、オフラインでも普通に使えます
- オフライン中の入力はブラウザに溜まり、つながった時点で自動送信されます
  （Firestore の永続キャッシュ）
- あいことばを知っていれば誰でも読み書きできます。グループ内で使う前提の強度なので、
  SNS などに貼らないでください
- 端末の時計が大きくずれていると、`config` の新旧判定を誤ることがあります
  （記録と進捗は時刻に依存しないため影響を受けません）

ビルド不要。ファイルを置くだけで動きます。実行時の外部通信は次の通りです。
どちらも失敗しても、端末内への記録と進捗管理は動きます。

- Google Fonts（丸ゴシックの代替）… iPad ではヒラギノ丸ゴ ProN が使われるため実質不要
- Firebase SDK / Authentication / Firestore … 端末間共有を使うときに読み込む

kuromoji.js と約17MBの辞書はリポジトリに同梱しており、「ぜんぶ ひらがなに して」を押したときだけ Web Worker から同じ配信元のファイルを読み込みます。

## デザインの方針

小学2年生が読めることを最優先に、ジャポニカ学習帳とラジオ体操カードを下敷きにしています。

- 地は方眼紙、文字は濃藍のインク色
- 区分は色で示す（赤＝かならずやる／黄＝つぎにやる／紫＝まいにち／緑＝できた）
- 進捗バーは常に緑。「できた量」を表すため、区分の色とは分けている
- カウントダウンの数字は方眼のマス目に1文字ずつ入れる
- 記録すると「できた！」のはんこが押される
- `prefers-reduced-motion` に対応
