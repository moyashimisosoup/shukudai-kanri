# はじめ夏休みの宿題

小学2年生が自分で使える、夏休みの宿題の進捗管理アプリ。
静的ファイルのみで動作し、GitHub Pages に置けば iPad の Safari から使えます。

## URL

| | URL |
|---|---|
| **こども用** | https://moyashimisosoup.github.io/shukudai-kanri/ |
| **親用（進捗一覧）** | https://moyashimisosoup.github.io/shukudai-kanri/#settings |
| 親用（設定） | https://moyashimisosoup.github.io/shukudai-kanri/#config |

こども用の画面は `のこりの しゅくだい / やったこと` の2タブだけです。記録の入力は
「のこりの しゅくだい」の各カードにある「やった！」から行うため、専用の記録タブは置いていません。
こども画面から親ページへの導線はなく、**親ページ → こども画面の一方通行**です。
親ページには「子ども画面へ」ボタンがあり、必要な操作はすべて親ページ内で完結します。

親ページを開くには URL に `#settings` を付けます。

それぞれの URL を別々にホーム画面に追加しておくと、開いた瞬間に目的の画面が出ます。

## できること

| 画面 | 内容 |
|---|---|
| **のこりの しゅくだい** | 夏休み終了までのカウントダウン（日・時・分・秒）、ペースメーター、残っている宿題の一覧、今日やったこと、なぞなぞ／豆知識。各カードの「やった！」から記録も入力する |
| **やったこと** | いつ・何を・どのくらいやったかの記録を日付ごとに表示 |
| **よんだ本**（`#books`） | 記録した本の一覧。紙のカードへ書き写しやすい大きさで並ぶ |
| **保護者ページ**（`#settings`） | 進捗の一覧が最初に出る。全体の残り・経過率・課題ごとの進捗表・本の記録一覧・進捗サマリー |
| **設定**（`#config`） | 保護者ページから移動。夏休みの期間、項目名、進捗の数え方、ノルマ、データのバックアップ |

画面は `#home` / `#log` / `#books` / `#settings` / `#config` のハッシュで切り替わるため、
それぞれを直接ブックマークできます。

### ペースメーター

このアプリの中心となる指標です。

```
なつやすみ  ▓▓▓▓▓▓▓▓░░░░░░░░  40%   ← 夏休みが何％過ぎたか
しゅくだい  ▓▓▓▓▓▓▓▓▓░░░░░░░  43%   ← 必須の宿題が何％終わったか
                いいペース！
```

下のバーが上のバーより先にあれば順調、という一目でわかる形にしています。
判定は次の通りです。

- `+8%` 以上 … よゆうだね！このちょうし！
- `±8%` 以内 … いいペース！
- `-6%` 以下 … すこし いそごう！
- `-18%` 以下 … きょうは がんばりどき！

### 進捗の数え方（3種類）

| 種類 | 使う場面 | 表示 |
|---|---|---|
| `count` 番号・かず | なつスキル①〜⑭、読書のきろく20冊など | 「つぎは ⑦」＋ 棒グラフ |
| `step` だんかい式 | 読書ゆうびん、エコチャレンジ、自由研究 | 「つぎは『絵をかく』」＋ 棒グラフ |
| `daily` まいにちノルマ | トドさんすう、シンクシンク | ハートの数＋連続日数 |

`count` は記録形式を「通常」と「本の記録」から選べます。

### 本の記録

読書のきろくのように1冊ずつ内容を残したい課題は、保護者ページで記録形式を「本の記録」にします。
入力欄は次の通りで、作者・出版社・おすすめ度は保護者ページから表示/非表示を切り替えられます。

- 本の なまえ（必須）
- さくしゃ／しゅっぱんしゃ（任意・切替可）
- よんだ日（既定は今日。あとから訂正可）
- おすすめ度 ★1〜3（任意・切替可）
- ひとこと感想

1件登録すると冊数が1つ進みます。記録した本は保護者ページの「本の記録」に一覧され、
書名・読んだ日・感想をあとから訂正できます。削除すると冊数も1つ戻り、通し番号は振り直されます。

#### 感想の漢字を2年生までに直す

感想を音声入力すると、習っていない漢字が混ざります。処理は2段階に分かれています。

**1段目「かんじを しらべる」— 通信なし・即時（実測 129ms）**

小1・小2の配当漢字240字の表と照合するだけなので、辞書は要りません。習っていない漢字を
一覧で示し、本文中の該当箇所にも色を付けます。

```
ならっていない かんじ：主　不　議　験　所　面
[主]人公が[不]思[議]な体[験]をする[所]が[面]白かった。友だちと読みたい。
```

**2段目「ぜんぶ ひらがなに して」— 辞書が必要**

読みを取るために形態素解析（kuromoji.js）を使い、習っていない漢字を含む語をまるごと
ひらがなに直した**書き写し用の文**を作ります。

```
主人公が不思議な体験をする所が面白かった。友だちと読みたい。
  ↓
しゅじんこうがふしぎなたいけんをするところがおもしろかった。友だちと読みたい。
```

「友だち」「読みたい」は友・読が小2配当なので漢字のまま残ります。

##### 辞書は Web Worker で動かす

kuromoji の辞書は**17MB をダウンロードし、95MB に展開**します。この展開と索引構築は
同期処理なので、メインスレッドで実行すると画面が数秒間フリーズします（実測：展開だけで
PC で 1.3 秒、構築を含め約 2 秒。iPad ではさらに数倍）。

そのため辞書は `assets/kanji-worker.js` の中だけで動かしています。実測でメインスレッドの
最大フレーム間隔は 29ms に収まり、読み込み中も画面は普通に触れます。

初回だけダウンロードが発生するので、**Wi-Fi 環境で最初の1回**を済ませてください。
画面にもサイズを明示しています。2回目以降はブラウザのキャッシュから読みます。
読み込めない場合でも1段目の結果は残るので、**記録そのものは必ず保存できます**。

`count` と `step` には「記録のとき出す質問」を設定できます。きゅうりの観察カードは
カード自体は1枚なので `step`（作業段階）で進捗を測り、観察の観点を質問として提示、
答えたものが記録に残ります。

### 進捗サマリー（保護者用）

`せってい → 進捗サマリー` で、今の状況をプレーンテキストに書き出せます。
コピーしてメールやメッセージに貼るか、`.txt` で保存できます。

```
■ はじめ夏休みの宿題一覧
8月6日（木） 23:42 時点

夏休み終了まで  あと 25日0時間
夏休みの経過  40%
必須の宿題    44%  (32/73)
できればやる  27%  (6/22)
判定  いいペース！

【かならずやる】
・なつスキル（こくご）  6/14ばん  43%  次は ⑦
・きゅうりの かんさつカード  2/5  40%  次は 「絵を かく」
✓ 学習用プリント（さんすう）  4/4まい  完了
...

【記録（直近7日）　4件】
8月6日（木）
  10:40  読書のきろく　20さつ … ⑦ できた
      ふしぎ駄菓子屋 銭天堂
```

記録の範囲は 直近7日／直近30日／全期間／含めない から選べます。

### 子どもの入力について

- 進捗の入力はすべて**タップによる選択**です。キーボード入力は不要です。
- メモ欄と観察カードの回答だけ自由記述ですが、書かなくても記録できます。
- iPad のキーボードのマイクボタンで音声入力できます。Chrome など
  Web Speech API が使えるブラウザでは 🎤 ボタンも表示されます。

## 使い方（初回）

1. `せってい` タブを開く
2. **なつやすみ おわり** を学校から配られた日付に合わせる（初期値は 2026/08/31 23:59）
3. 必要なら項目名・冊数・段階を実物に合わせて調整する

初期設定の以下の項目は、配布物が手元にないため推定で入れています。実物に合わせて調整してください。

- きゅうりのかんさつカード … 1枚。「よく見る → 高さを測る → 絵を描く → 気づいたことを書く → 日付と名前」の5段階
- なかのエコチャレンジ … 「やることを決める → 1〜7日め → 感想を書く」の9段階

## GitHub Pages への公開

```bash
cd "C:\Users\user\AI開発\shukudai-kanri"
git remote add origin https://github.com/<ユーザー名>/<リポジトリ名>.git
git branch -M main
git push -u origin main
```

GitHub のリポジトリで **Settings → Pages → Source: Deploy from a branch → main / (root)** を選ぶと、
数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます。

iPad の Safari でそのURLを開き、共有ボタンから **ホーム画面に追加** すると、
アドレスバーのないアプリのように使えます。こども用（`/`）と親用（`/#settings`）を
別々に追加しておくと、それぞれのアイコンから直接その画面が開きます。

## データの保存場所

記録は **その端末の localStorage** に保存されます。

- Safari の履歴／サイトデータを消すと記録も消えます
- `せってい → データ → 書き出す` で JSON にバックアップできます。
  復元は同じ画面の `読みこむ` から
- 端末をまたいで共有したい場合は、次の「端末間で共有する」を設定します

## 端末間で共有する

初期状態では端末ごとに独立して保存されるため、子の iPad で入力した内容は親の端末には現れません
（消えたのではなく、そちらには最初から無い）。Firebase Firestore をつなぐと自動でそろいます。

設定していなければこれまで通り端末内だけに保存され、通信は一切発生しません。

### 1. Firebase プロジェクトを作る

1. https://console.firebase.google.com/ で「プロジェクトを追加」（Google アカウントが要ります）
2. `構築 → Firestore Database → データベースの作成`。ロケーションは `asia-northeast1`、
   モードは「本番環境」を選ぶ
3. `構築 → Authentication → 始める → Sign-in method → 匿名` を有効にする
4. `プロジェクトの設定 → マイアプリ → </> ウェブ` でアプリを登録し、表示された
   `firebaseConfig` の中身を控える

### 2. 設定を貼る

`assets/sync.js` 冒頭の `FIREBASE_CONFIG` に、控えた値を入れます。

```js
const FIREBASE_CONFIG = {
  apiKey:            'AIza...',
  authDomain:        'xxxx.firebaseapp.com',
  projectId:         'xxxx',
  storageBucket:     'xxxx.firebasestorage.app',
  messagingSenderId: '000000000000',
  appId:             '1:0000:web:0000'
};
```

この値は公開されても問題ないもので、アクセス制御は次のセキュリティルールで行います。

### 3. セキュリティルールを設定する

`Firestore Database → ルール` を次の内容に置き換えて公開します。

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /households/{houseId} {
      allow read, write: if request.auth != null && houseId.size() >= 16;
    }
  }
}
```

### 4. 端末をつなぐ

1. 親の端末で `#config` を開き、**べつの端末と つなぐ → ✨ 新しく作る → この あいことばで つなぐ**
2. 「コピー」で20文字のあいことばを控え、子の端末の同じ欄に貼って「この あいことばで つなぐ」
3. 見出しの右が `✓ つながっています` になれば完了

以後、どちらの端末で入力しても数秒で反映されます。

### 合わせ方の方針

**子どもの入力が消えないことを最優先**にしています。

| データ | 合わせ方 |
|---|---|
| `logs`・`books` 記録 | id で突き合わせて**両端末ぶんを足す**。同じ id は新しい方 |
| `progress.done` 番号・冊数 | **大きい方**を採る |
| `progress.days` 毎日ノルマ | 日付ごとに全部あわせ、同じ日は多い方 |
| `progress.steps`・`wrap` 段階 | どちらかでチェック済みなら**チェック済みのまま** |
| `config` 設定 | **後に保存した方で丸ごと置き換え**（設定は保護者が行う前提） |
| `fun` なぞなぞの残り回数 | 共有しない（端末ごとに1日3回） |

進捗を時刻の新旧だけで決めると、子がオフラインで⑦まで進めている間に保護者ページを開いた
だけで、古い⑥が後から上書きして子の作業が消えます。数は減らないものとして扱うことで、
どちらが先に届いても同じ結果になります。

なお `fun`（なぞなぞ・豆知識の1日3回）を共有すると、保護者がページを開いただけで
子の回数が減ってしまうため、これだけは送信しません。

### 制約

- **引き算の訂正は相手の端末に届きません。** 「⑦を⑥に戻す」「本の記録を消す」といった
  訂正は、その操作をした端末以外がオフラインだった場合、復活することがあります。
  訂正は子の端末で行ってください
- 保存の主体は今も localStorage です。起動は通信を待たず、オフラインでも普通に使えます
- オフライン中の入力はブラウザに溜まり、つながった時点で自動送信されます
  （Firestore の永続キャッシュ）
- あいことばを知っていれば誰でも読み書きできます。家庭内で使う前提の強度なので、
  SNS などに貼らないでください
- 端末の時計が大きくずれていると、`config` の新旧判定を誤ることがあります
  （記録と進捗は時刻に依存しないため影響を受けません）

## ファイル構成

```
index.html                    画面の骨組みとタブ
assets/style.css              デザイン（方眼紙・色帯・はんこ）
assets/data.js                初期設定の宿題データ、なぞなぞ・豆知識
assets/kanji.js               小2までの配当漢字の判定と書き写し用の変換
assets/kanji-worker.js        形態素解析（メインスレッドを止めないため分離）
assets/app.js                 進捗計算、描画、記録、設定
assets/sync.js                端末間の共有（Firestore・未設定なら何もしない）
.github/workflows/pages.yml   GitHub Pages へのデプロイ
.nojekyll                     Jekyll 処理を無効化
```

ビルド不要。ファイルを置くだけで動きます。外部への通信は次の2つだけで、
どちらも失敗してもアプリの記録機能は動きます。

- Google Fonts（丸ゴシックの代替）… iPad ではヒラギノ丸ゴ ProN が使われるため実質不要
- kuromoji.js（感想の漢字変換）… 「ぜんぶ ひらがなに して」を押したときだけ、
  Web Worker の中で読み込む。辞書は約17MB

## デザインの方針

小学2年生が読めることを最優先に、ジャポニカ学習帳とラジオ体操カードを下敷きにしています。

- 地は方眼紙、文字は濃藍のインク色
- 区分は色で示す（赤＝必ずやる／黄＝できればやる／紫＝毎日／緑＝できた）
- 進捗バーは常に緑。「できた量」を表すため、区分の色とは分けている
- カウントダウンの数字は方眼のマス目に1文字ずつ入れる
- 記録すると「できた！」のはんこが押される
- `prefers-reduced-motion` に対応
